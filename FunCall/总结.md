# PPT Master - FunCall 服务项目演进总结

本项目旨在为处于**离线局域网环境**下的用户，将 `ppt-master` 演示文稿生成的核心逻辑抽象为智能体（Agent）的 Function Calling 工具集，并构建一套前后端高度整合的低代码 PPT 实时预览与人机协同生成服务。

## 1. 核心需求与架构演进里程碑

整个会话期间，系统经历了以下四个核心阶段的演进：

```
+------------------+     +--------------------+     +---------------------+     +--------------------+
| 阶段一: 工具封装  | --> | 阶段二: 智能体构建   | --> | 阶段三: 交互面板统一 | --> | 阶段四: 流数据重构  |
| 脚本抽象与接口封装|     | LangGraph 路由与回圈|     | 局域网编辑与隔离沙箱 |     | NDJSON原生增量协议 |
+------------------+     +--------------------+     +---------------------+     +--------------------+
```

### 阶段一：核心流水线工具化与封装
* **需求**：把 `skills/ppt-master/scripts/` 下分散的原始 Python 脚本提取为 LLM 可调用的原生接口。
* **实现**：
  - 创建了 `ppt_tools.py`：使用 Python `subprocess` 封装了初始化项目、源文档 Markdown 转换、LaTeX 渲染、AI 图像生成、SVG 合并及 PPTX 导出等核心子过程，同时为大模型增设了文件和目录读写工具（`read_file`、`list_dir`）。
  - 创建了 `tool_schemas.py`：自动导出 19 个工具的标准 OpenAI Tool Calling 描述与 Gemini FunctionDeclaration。
  - 创建了 `run_pipeline.py` 作为 CLI 本地运行入口。

### 阶段二：基于 LangGraph 的本地 Agent 重构
* **需求**：在离线环境下使用本地大模型（如 Ollama, LM Studio）驱动长链工具流，防止大模型陷入逻辑回圈。
* **实现**：
  - 重构 `local_agent.py`，采用 LangGraph 的 `StateGraph` 实现 ReAct 运行循环。
  - **防止死循环拦截**：编写了 `check_tool_has_succeeded` 检测机制。对路径参数采用正反斜杠及大小写标准化（`normalize_tool_args`），防止大模型通过微调路径来重复调用已成功的初始化或导入命令。

### 阶段三：FastAPI 统一服务与前端 React 协同画板（WrenAI 审美对齐）
* **需求**：取代之前繁杂的 Flask 分离服务，打造单端口局域网极简部署、且多会话目录隔离的实时可视化生成面板。
* **实现**：
  - **统一服务 app.py**：单端口 5050 同时托管 REST APIs、对话流及前端 React 静态单文件。
  - **Cookie 会话动态路由与沙箱沙盒**：通过 `/{session_id}` 入口访问时自动下发 Cookie。在工具拦截器中实现 `sanitize_session_paths`，对大模型做出的任何偏航路径参数（如 `quantum_computing/...`）进行递归重写，绑定在专属的 `projects/{session_id}_*` 下，实现完美的并行沙盒隔离。
  - **系统提示词动态同步**：解决了历史会话重启时加载旧 SystemMessage 导致无法执行新功能的问题，后端在检测到会话重启时通过 `agent_app.update_state` 动态覆写并对齐最新指令集。
  - **React 纯净画板 (FunCall_ui)**：构建了无需 iframe 渲染的 SVG 高亮点击修改机制、侧边折叠聊天窗、实时可视化执行步骤条以及 PPTX 直接打包下载。

### 阶段四：流式传输重构（NDJSON 协议化）
* **需求**：解决原有 SSE 协议混合控制台日志流与大模型原生输出在前端难以增量合并、易覆盖的脆弱性。
* **实现**：
  - **后端**：在 `app.py` 中去除 Console 拦截日志管道 `log_queue`，将媒体类型重构为 `application/x-ndjson`；使 `/api/agent/run` 原生输出 `astream` 逐行 JSON 文本，并确保了 `/api/agent/history` 能全量追溯 Tool 和 System 消息。
  - **前端 App.tsx**：使用 NDJSON 解析算法，配合稳定消息 ID 对大模型增量输出做就地更新（Deduplication）；并在画板主列表中隐藏原始 `tool`/`system` 消息，统一通过 `toolResultsMap` 优雅呈现在 collapsible 折叠式执行状态树中。
